## 0. 배경과 설계 원칙

### 0-1. 시험 구조 (모든 설계의 근거)
- 1차 시험 = 교육학 논술 1문항 20점(60분) + 전공A 12문항 40점(90분, 기입형 2점×4 + 서술형 4점×8) + 전공B 11문항 40점(2점×2 + 4점×9).
- 전공 "서술형" = 긴 논술이 아니라 `자료 + <조건> + <작성 방법>` 구조의 정밀 단답·계산·코드·1~3문장 서술.
- 매 시험지 3~4문항(전체 ~26점/100점)이 **2022 개정 정보과 교육과정** 문항 (내용 요소·성취기준·교수학습·평가 용어를 고시문 표현 그대로 요구).
- 교육학은 재인(객관식) 문항이 시험에 존재하지 않음 — 최종 목표는 논술.

### 0-2. 사용자 기질 기반 UX 하드 규칙 (전 화면 공통, 위반 금지)
사용자 TCI: 자극추구 매우 높음 / 예기불안 높음 / 자기비판 매우 강함. 따라서:

1. **"빚" 지표 노출 금지**: 밀린 카드 수, 미완료 수, 연속 실패 등을 어떤 화면에도 표시하지 않는다.
2. **스트릭(연속 일수) 금지**: 끊기는 지표를 만들지 않는다. 지표는 누적형(오르기만 하는 것)만: "지금까지 복습한 카드 N장", "정복한 개념 N개".
3. **일일 큐는 항상 끝낼 수 있는 크기**: 하루 상한 기본값 = 복습 15장 + 신규 10장 (설정에서 변경 가능). 상한 초과분은 자동 이월하며 이월 사실을 사용자에게 알리지 않는다.
4. **아침 결정 제로**: 접속 즉시 "오늘 할 것"이 이미 정해져 있어야 한다. 선택지를 먼저 내밀지 않는다.
5. **세션 종료 화면은 성취만 표시**: "오늘 N장 완료, 누적 M장". 남은 것·못한 것 언급 금지.

### 0-3. 범위
- **포함**: DB 스키마 확장(§1), 기출 문제은행(§2), 교과교육학 트랙(§3), 오늘의 복습 홈(§4), 교육학 3단계 사다리(§5), 채점 엄격화(§6), API/화면 목록(§7), 마이그레이션·수용 기준(§8).
- **제외 (후속 Phase)**: 뽀모도로(focus-app) 연동 구현 — 단, §7의 `/api/today-plan` 응답 형식만 이번에 확정. 사진 채점 자동화. SQL/C 실행 환경 통합. 보안 하드닝(별도 진행 중).

## 4. 오늘의 복습 홈 (프론트 개편)

### 4-1. 홈 화면 (`/`) 전면 교체
- 접속 즉시 표시: **"오늘의 복습 N개 · 약 M분"** 단일 대형 CTA. (M = N × 문항당 평균 45초, 올림)
- N = min(일일 상한, due 카드 수). due가 0이면 "오늘 분량 완료" 상태 + 누적 지표 + "더 풀기(신규 문제)" 보조 버튼.
- 하단에 작은 보조 링크: 문제은행 탐색 / 약점 보기 / 교재 관리(기존 홈 기능 이전) / 검수함 / 설정.
- **모바일 우선 레이아웃** (Lightsail 배포본을 폰·아이패드에서 사용). ~~PWA manifest~~ → **사용자가 도메인/HTTPS 미도입 결정(2026-07-08) — HTTP에서 PWA 불가.** 브라우저 "홈 화면에 추가" 바로가기로 대체. 반응형 + Basic Auth 세션 유지만 보장할 것.

### 4-2. 통합 큐 로직 (`GET /api/review/today`)
- 전체 book·트랙 통합: `sr_concepts`에서 due(next_review_at ≤ now)인 개념을 뽑고, 각 개념마다 출제할 문항 1개를 선택.
- **문항 선택 우선순위**: ① 그 개념의 기출 원문항 중 최근 30일 내 미출제분 → ② 기존 생성 문항 중 미출제분 → ③ 신규 변형 생성 (동기 생성이 3초 초과 시 ②로 폴백하고 백그라운드로 생성해 다음 회차에 사용).
- **인터리빙**: 같은 subject가 3연속 나오지 않도록 셔플.
- **디바이스 필터**: 요청 파라미터로 뷰포트 구분을 받아 모바일이면 `desk_only=true` 문항을 가진 개념은 대체 문항을 찾고, 없으면 그 개념을 건너뛴다(다음 데스크톱 세션으로 이월).
- 응답에 due 총수를 포함하지 않는다 (상한 잘라낸 목록만). — §0-2 규칙 1.

### 4-3. 백로그 사면 (1회성 마이그레이션, `POST /api/review/amnesty`)
- 현재 밀린 카드(≈126장, 문항 단위)를 §8-1 규칙으로 개념 단위로 변환한 뒤, `next_review_at`을 **오늘부터 14일에 걸쳐 균등 분산** 재배정 (ease/interval/repetition은 보존).
- 관리 설정 화면에서 버튼으로 실행. 실행 후 홈에는 그냥 "오늘의 복습 N개"만 보인다.

### 4-4. 복습 세션 화면
- 카드 1장씩. 답 제출 → 즉시 채점·피드백 → 다음. 중도 이탈해도 푼 것까지 저장.
- 종료 화면: "오늘 N장 완료 · 누적 M장 · 정복한 개념 K개". 그 외 지표 금지.
- 기존 `/review` 페이지의 오류 무시 문제 수정: API 실패 시 "다시 시도" UI 표시 (현재는 catch 없이 '불러오는 중'에 멈춤 — `review/page.tsx`).

| 1 재인 | mcq / matching | **신규·미학습 개념에 한해** 사용자가 "아직 모르는 개념" 플래그를 준 경우만. 같은 개념 2회 연속 정답 → stage 2로 자동 승급 |
| 2 단문 인출 | short_answer ("~을 2~3문장으로 서술") | **기본값** (1회독 완료 상태이므로). 핵심어 루브릭 채점(§6-2)에서 3회 연속 전 개념 hit → "정복" 표시(SR은 계속) |
| 3 논술 | 기출 형식 전문 작성 | 스케줄 기반 (자동 큐가 아님): 7~8월 월 1회, 9월~ 격주, 10월~ 주 1회 권장 배너 표시 |

- mcq/matching **신규 생성은 stage 1 요청 시에만** 허용. 기본 생성 유형에서 제거 (main.py의 생성·prebuild 경로).
- 기존 mcq/matching 149문항: 삭제하지 않되 `active=false` 처리 (stage 1 개념에서만 재활성).

### 5-2. 변형 문제 생성 규칙 (전공 공통)
- 개념 복습 시 새 문항을 만들 때, 그 개념과 연결된 **기출 문항을 스타일 예시로 프롬프트에 주입** (임베딩 유사도 상위 2~3개).
- 전공 변형은 기출의 `<조건> + <작성 방법>` 골격을 유지: 정의를 제시하고 실행을 요구하는 형태로. "~을 설명하시오"식 개방형 금지.
- 생성 문항은 `active=true`로 바로 큐 투입 가능하되 `answer_verified=false` 배지 유지.

### 5-3. stage 3 논술 화면 (`/essay-exam`)
- 교육학 기출(2023~2026) 또는 LLM 생성 유사 세트 선택 → 제시문 + 4개 하위 요구 + **60분 카운트다운**.
- 답안 입력: 텍스트 영역 **또는 사진 업로드**(손글씨 답안 촬영).
- 채점: Claude에게 채점기준표 형식(항목별 배점, 서·본·결 구성 점수 포함)으로 구조화 채점 요청 → `user_answers`에 저장, 항목별 판정을 `concept_results`로 기록.
- 결과 화면: 항목별 득점 + 누락 개념 목록. 누락 개념의 SR을 즉시 due로 앞당김.

## 6. 채점 엄격화 (SR 오염 방지 — 필수)

### 6-1. 빈칸(fill_blank)
- 현행 양방향 부분 문자열 매칭(`u in p or p in u`)을 폐기.
- 규칙: ① 정규화(NFC, 공백/괄호 제거) 후 **완전 일치 우선** ② 부분 일치는 "사용자 답 ⊇ 정답" 방향만 허용 ③ 사용자 답 길이가 정답의 60% 미만이면 무조건 오답. (근거: "발달"이 "근접발달영역"의 부분 문자열이라 정답 처리되는 현행 버그 — backend-analysis §6-(6))
- 교과교육 카드(`subject='교과교육'`)는 **완전 일치만** 인정 (고시문 용어 시험이므로).

### 6-2. 서술(short_answer / essay)
- 채점 응답을 구조화 강제: `{ score(0~1), feedback, concepts: [{concept_id 또는 name, verdict: hit|missing|misconception, evidence(한 줄)}] }`
- 응답 키 존재를 검증하고 범위 클램프 (backend-analysis §6-(7)의 KeyError 방지 포함).
- `missing`/`misconception`이 하나라도 있으면 SM-2 quality 상한을 3으로 캡 (점수가 높아도 간격이 크게 벌어지지 않게).

### 6-3. SM-2 갱신
- 채점 점수 → quality 변환은 현행 유지하되, 위 6-2 캡 적용.
- `update_sr_card` 대상을 `sr_concepts`로 변경. 한 문항이 여러 개념에 걸리면 개념별 verdict로 각각 갱신 (hit=quality 원값, missing=2, misconception=1).

## 9. 파트별 학습 모드 (교육학 한정) — 2026-07-18 추가

### 9-0. 배경 (왜 이걸 만드는가)
사용자가 별도로 쓰던 단일 HTML 연습지(`정보컴퓨터_복습/CA_명령어사이클_파트별.html`)를 실사용한 뒤 나온 피드백:
① **"파트별로 문제를 내주는 게 좋겠다"** — 28문제를 한 화면에 쏟아내면 부담. 한 덩어리씩.
② **"문제 후에 바로 상세한 해설 있는 게 좋다"** — 특히 *왜 그런지* + 비유가 있는 해설.

이 포맷은 **습득(acquisition) 단계**용이다. §4의 오늘의 복습(과목 인터리빙)은 **유지(retention) 단계**용이므로 둘은 경쟁하지 않고 역할이 다르다 — 처음 배울 땐 blocked, 익힌 뒤엔 interleaved가 학습과학의 정석.

단일 HTML의 치명적 한계는 **기록이 localStorage에 갇혀 약점·SR에 반영되지 않는다**는 것. 그래서 같은 경험을 study-app 안으로 이식해 답안이 `user_answers`로 흘러가게 한다. 이것이 이 기능의 존재 이유다.

**범위: 교육학만.** 전공은 기출 문제은행이 담당하므로 이번 범위 밖.

### 9-1. 구조 매핑 (실측 데이터 기준)
`lectures` 78강 / 대영역 9개 / 강의당 문제 4~10개.

- **코스 = 대영역(`lectures.part`)** — 예: "PART2 교육과정"(15강), "PART3 교육방법 및 공학"(16강)
- **파트 = 강의(lecture)** — 그 강의에 연결된 문제 전부가 한 파트
- 별도 진행도 테이블을 만들지 않는다. **진행률은 `user_answers` 기반으로 계산**(그 강의 문항 중 답한 개수). `lecture_progress`는 게임 모드 전용이므로 건드리지 않는다.

### 9-2. 화면 흐름 (`/learn`)
1. **대영역 선택** — 9개 카드, 각각 "15강 중 3강 완료" 진행률. 진행 중인 영역이 맨 위.
2. **파트 진행** — 영역을 고르면 *가장 먼저 안 끝난 파트*로 자동 진입(§0-2 "아침 결정 제로"). 상단에 파트 칩(1..N)으로 이동 가능.
3. **파트 내부** — 그 강의의 문제를 **쉬운 유형 → 어려운 유형 순**(mcq → matching → fill_blank → essay)으로 제시. 한 문제 답하면 **즉시 채점 + 해설**, 그 문항은 잠금(정답 보기 표시).
4. **파트 완료** — "N문제 중 M개 맞았어요" + 틀린 문항 번호 + [틀린 것만 다시 풀기] [다음 파트 →].
5. 중간 이탈 자유. 답한 것까지 서버에 남으므로 재진입 시 복원된다.

### 9-3. 유형 정책 (§5-1과의 관계)
`mcq`/`matching`은 §5-1에 따라 `active=false`(복습 큐 제외)지만, **학습 모드에서는 포함한다.** 학습 모드가 곧 stage 1(재인 → 회상 진입로)이기 때문. 즉 `active` 플래그는 "복습 큐 편입 여부"이지 "사용 가능 여부"가 아니다.

### 9-4. 해설 요구사항 (핵심 — 이게 없으면 이 모드는 의미가 없다)
실측: 강의 연결 문항 668개 중 `explanation` 보유는 mcq 64개뿐. **fill_blank 65 + matching 64 = 129개가 해설 0개.**

- 표시 우선순위: `question_data.explanation` → (essay) `model_answer` → (fill_blank) `hints`
- 없는 129개는 **일회성 LLM 배치로 백필**한다. 품질 기준은 CA 파일 수준 — *정답이 무엇인지*가 아니라 **왜 그런지 + 기억에 남는 비유/대비**. 예: "버스는 좁은 복도 하나라서 한 번에 한 명만 지나가."
- 앞으로 생성되는 문항은 §생성 프롬프트에서 전 유형 `explanation` 필수(이미 key_concepts 추가 시 함께 반영됨 — 추가 보강 필요).

### 9-7. 서술형 2단계 분리 (키워드 회상 → 문장 작성) — 2026-08-07 추가

**배경 (사용자 피드백):** "문장으로 쓰는 건 안 되는데 단답형이랑 같이 나오더라고. 다음 단계로 빼면 좋겠다."

**제약 (실측):** 강의 연결 문항 668개 중 **서술형이 475개**, 그리고 **강의 65개 중 42개는 서술형뿐**이다.
따라서 "서술형을 세션에서 제외"하면 교육학 강의 3분의 2가 1단계에 내줄 문제가 0개가 된다.
→ **문항을 빼는 대신 답변 요구 수준을 낮춘다.**

| 단계 | 서술형 제시 방식 | 채점 |
|---|---|---|
| 1단계 (기본) | `KeywordRecall` — 핵심 개념어만 인출. 한 줄 입력 | `_grade_keyword_recall` (로컬, LLM 호출 없음). 핵심 개념 포함 비율, `KEYWORD_HIT_RATIO=0.6` 이상이면 정답 |
| 2단계 (선택) | `Essay` — 문장으로 작성 | 기존 `grade_essay` (LLM) |

- **핵심 개념은 답하기 전에 절대 노출하지 않는다** — 노출하면 회상이 아니라 읽기가 되어 카드의 의미가 사라진다.
- 답한 직후 회상/누락 개념을 ✓/✗로 보여주고 모범답안을 바로 편다(접지 않음).
- **SR 상한 `KEYWORD_QUALITY_CAP=4`** — 키워드 회상은 서술보다 쉬운 인출이라 만점이어도 '숙달'로 보지 않는다. 상한이 없으면 문장을 못 쓰는 개념이 복습 큐에서 조기 이탈한다.
- 2단계는 **원할 때 고르는 추가 패스**이지 밀린 과제가 아니다(§0-2). 세트 완료 시점에만 제안하고, 목록 화면에는 누적 개수를 절대 표시하지 않는다.
- 2단계는 이미 푼 문항도 다시 내준다 — 같은 문제를 더 높은 요구 수준으로 한 번 더 보는 패스이므로.
- **오늘의 복습(`/review`)의 서술형은 항상 1단계(키워드)** — 매일 도는 큐를 문장 작성으로 막지 않는다.

**유형 시각 구분** (같은 피드백의 나머지 절반 — 단답형과 서술형이 둘 다 동일한 textarea라 구분이 안 됐다):

| 유형 | 배지 | 입력 |
|---|---|---|
| `short_answer` | 단답 (teal) | 한 줄 `<input>`, 최소 1자 |
| `essay` 1단계 | 서술형 + "키워드만" (indigo) | 한 줄 `<input>` |
| `essay` 2단계 | 서술형 (indigo) | 8행 `<textarea>`, 최소 20자 |

**API:** `GET /learn/parts/{id}?stage=1|2`, `POST /sessions/answer` 에 `mode: "full"|"keyword"` 추가.
응답에 `stage`/`essay_total`(세션), `recalled`/`missed`(채점) 추가.
