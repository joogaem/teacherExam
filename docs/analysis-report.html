1. 프로젝트 개요

설보연 교육학 교재(2권, ~1,600p PDF)를 RAG로 구축하여 임용고시 수준 문제를 자동 생성·채점하는 개인 학습 플랫폼.

구분기술
백엔드FastAPI + uvicorn (Python 3.12)
프론트엔드Next.js 16 + React 19 + Tailwind
DBSupabase (PostgreSQL + pgvector)
임베딩Voyage AI voyage-3 (1024차원)
문제 생성·채점Claude claude-sonnet-4-5
복습SM-2 Spaced Repetition
PDF → PyMuPDF 추출 → 청킹 → Voyage 임베딩 → Supabase pgvector ↓ 사용자 요청 → 벡터 검색(top-k) → Claude 문제 생성 → 풀이/채점 → SR 카드 갱신

DB 핵심 테이블

  • books · chunks(임베딩+ivfflat) · questions(JSONB)
  • lectures 신규 — 78강 커리큘럼 (페이지 범위 포함)
  • questions.lecture_id 신규 — 강의별 문제은행
  • quiz_sessions / user_answers / sr_cards
Supabase는 두 컴퓨터가 공유하는 단일 프로젝트 — 코드만 깃으로 동기화, 데이터는 자동 공유.

2. 이번 작업 내역

2-1. 강의별 문제풀기 (78강)

  • 페이지 오프셋 보정 — 인쇄 페이지 ≠ PDF 페이지. 실측 앵커 + 선형 보간 (1권: 오프셋 증가형, 2권: ~0)
  • 하이브리드 검색 — 페이지 윈도우 점진 확장(±25→±60→±150) + 시맨틱, 미달 시 전권 폴백
  • PART 중복 주제 분리 — 동기이론이 교육행정(강56)과 교육심리(강71)에 모두 있어도 페이지 윈도우로 정확히 구분
  • API 4종 — 강의 목록 / 강의별 생성 / 문제은행 조회 / 사전 생성(prebuild)
  • UI — 강의별·챕터별 모드 토글, PART별 그룹 선택, 문제은행 버튼

2-2. 성능·토큰 최적화

통합 생성: 유형별 Claude 호출(4회) → 전 유형 1회 호출. 동일 교재 컨텍스트의 중복 전송이 사라져 입력 토큰 ~1/4, 응답 대기도 1회로 단축. DB 저장도 배치 insert로 전환.

2-3. 해결한 버그

버그원인 → 해결
특정 강의 검색 0건ivfflat 근사검색 + book_id 필터 = recall 구멍 → enable_indexscan=off 정밀검색
JSON 파싱 실패Claude가 설명문 혼입 → 괄호 범위 추출 폴백 파서

강15 오답 검색청크 희소 구간에서 타 PART 폴백 → 점진 윈도우가 ±60에서 포착

4. 효율성 평가

잘된 점

  • 토큰: 통합 생성으로 컨텍스트 중복 제거 (~1/4)
  • 속도: API 4회→1회, insert N회→1회
  • 정확도: 페이지+시맨틱 하이브리드로 중복 주제 분리
  • 비용: 기존 인스턴스 합승 — 추가 0원
  • 안정성: systemd 자동복구 + 스왑 보험 + 빌드 분리

한계 (1인 사용 전제로 수용)

  • enable_indexscan=off — 청크 수십만 개 규모가 되면 재검토 (현재 수천 개, 무관)
  • HTTP 평문 — 도메인 없어 HTTPS 미적용. 추후 도메인 연결 시 Caddy + Let's Encrypt 권장
  • 인증 없음 — URL 아는 사람은 접속 가능. API 키는 서버에만 있어 유출 위험 낮음

5. 기술 선택 의사결정 기록

작업 중 실제로 검토했던 대안과 최종 선택의 근거.

5-1. 배포 위치 — Lightsail 기존 인스턴스 합승

검토한 대안탈락 이유
Tailscale (VPN)설정은 가장 쉬우나 설치된 본인 기기만 접속 가능 — 아무 브라우저에서나 못 엶
집 공유기 포트포워딩동적 IP로 주소 수시 변경, ISP 차단 가능성, 집 PC 상시 가동 필요
Vercel(프론트) + Lightsail(백엔드)Vercel은 HTTPS 강제 → HTTP 백엔드 호출 시 혼합 콘텐츠 차단. 도메인이 없어 백엔드 HTTPS화 불가
✅ 전부 Lightsail + IP 접속HTTP↔HTTP라 차단 없음, 고정 IP, 합승으로 추가 비용 0원, 도메인 불필요

5-2. 빌드 전략 — 로컬 빌드 + standalone 번들

검토한 대안탈락 이유
서버에서 npm install + build1GB RAM에서 OOM으로 SSH 마비 2회 실제 발생 — 스왑을 붙여도 재발
.next만 업로드 + 서버 npm installnext start가 node_modules를 요구해 결국 npm install을 못 피함
✅ 로컬 standalone 빌드 → 3.5MB 업로드Next.js가 필요 파일만 추려 자체 server.js 생성 → 서버는 실행만

5-3. 프로세스 관리 — systemd (PM2 탈락)

  • PM2는 npm install -g 설치 자체가 OOM 유발 작업이었음
  • systemd는 OS 내장 — 설치 0, 부팅 자동시작, 크래시 5초 후 자동 재시작
  • 기존 봇 3종도 systemd 운영 중 → 서버 관리 방식 일관

5-4. 포트 8001 / 스왑 2GB

  • 배포 전 점검에서 schedulingBot이 8000 선점 확인 → 8001 회피. 합승 시 포트 점유 확인이 먼저
  • 스왑은 OOM 재발 방지 보험 — 운영 측정 결과 사용량 0B, 순수 안전장치로 동작

5-5. 통합 생성 (유형별 호출 폐기)

검토한 대안평가
프롬프트 캐싱토큰만 절감 — 호출 횟수(대기시간) 그대로
유형별 병렬 호출속도만 개선 — 컨텍스트 중복 전송 그대로
✅ 전 유형 1회 통합 생성토큰 + 속도 동시 달성 — 컨텍스트 1회 전송, 4유형 1회 수신

5-6. 검색 관련 결정

  • enable_indexscan=off — 1차 시도 ivfflat.probes는 Supabase 권한 거부(42501). 청크가 수천 개라 정밀검색 비용 무시 가능, 수십만 규모 시 재검토
  • 점진 윈도우 확장(±25→±60→±150) — 고정 좁은 윈도우는 희소 구간에서 0건, 전권 검색은 타 PART 오답(강15 타일러 사례). 좁게 시작해 정확도 우선, 부족할 때만 확장
  • 앵커 보간 — 1권은 오프셋이 뒤로 갈수록 커져(+1→+6) 고정값 불가. 실측 앵커 선형 보간으로 책별 패턴 흡수
